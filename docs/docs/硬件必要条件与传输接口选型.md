# 麦克风/摄像头必要条件与传输路线选型 v2（2026-09-15 采购前调研）

> v2 变更：确认"网络直连麦克风"真实存在（安防行业的网络拾音器），
> 路线收敛为 A（USB+会场电脑）vs C（纯网络设备）两路线对决，B 删除。

## 一、麦克风的必要条件（不满足=退货）

| # | 条件 | 为什么 | 怎么验 |
|---|---|---|---|
| 1 | **全向 360° 远场拾音**，拾音半径 ≥ 会议室半径（小会室 3~5m） | 多人围坐远场收音，手持/领夹/定向麦不合格 | 商品页"拾音半径"；实测坐远说话 |
| 2 | 路线 A：USB 免驱 UAC；路线 C：**RTSP/ONVIF 或 GB28181** | 蓝牙压缩音质不可接受；网络协议是 C 路线的生命线 | 商品页协议说明 |
| 3 | **采样率 ≥16kHz** | ASR 输入要求 | 参数页 |
| 4 | 路线 A 需内置 **AEC+降噪**；路线 C：降噪必需、**AEC 可放宽** | 会场不放音时回声不存在，AEC 非必需；降噪必须有 | 实测 |
| 5 | AGC 可关 | 过度压缩影响 VAD 判定 | 配套软件 |
| 6 | 大会议室支持级联/多机 | 8 人以上单机覆盖不住 | 商品页 |

价位锚点（沿用 02 号调研）：全向麦 eMeet M2（~900-1400）/ M2 Max（~1800-2800）/ Poly Sync 60（~3500-5000）；**网络拾音器为数百元级**（峰火/邮科/星浩等安防品牌，品控需实测）。

## 二、摄像头的必要条件（不满足=退货）

| # | 条件 | 为什么 | 怎么验 |
|---|---|---|---|
| 1 | **分辨率 ≥4K**（路线 A 消费款）/ ≥400 万像素（路线 C 安防款） | VLM 读字要像素 | D1 三连测 |
| 2 | **曝光可锁定/文档模式** | 自动曝光帧间跳变干扰一切下游 | 配套软件；选会议/文档定位款 |
| 3 | 对焦稳定 | 自动对焦抽搐=虚帧+误差分 | 实拍观察 |
| 4 | 视场覆盖 PPT 屏+白板 | 单机位盖两面墙，或双机位 | D1 第③测 |
| 5 | 路线 A：UVC 免驱 USB；路线 C：**RTSP/ONVIF**，PoE 供电优先 | 见路线对决 | 商品页 |
| 6 | 帧率 ≥15fps 足够、1/4 螺口 | 我们只要快照流 | — |
| 7 | 低照度不重要 | 会议室开灯 | — |

候选：路线 A — Insta360 Link / 罗技 MX Brio / 文档摄像头类（1500~2500）；路线 C — 海康/大华会议级网络摄像机或 4K 安防款（数百~两千）。

## 三、路线对决：A（USB+会场电脑） vs C（纯网络设备）

**两路线都成立的实物前提（已查证）**：
- 摄像头网络直连：✅ 成熟，IP 摄像头 RTSP/ONVIF 是它的本职工作
- 麦克风网络直连：✅ 存在——**安防行业"网络拾音器"**（[峰火 FH-300N](http://www.peakfire.cn/product/pk/647.html)：全向、16K~48K、拾音半径 0~10m 可调；[HD-B-1001](http://www.peakfire.cn/znwl/hxcp/401.html)：动态降噪；[淘宝 RTSP/ONVIF 款](https://www.taobao.com/list/item/RWh0TjdOSm9LYnpRdnBkSmdrd1Vtdz09.htm)）。要"设备主动推到固定地址"选支持 **GB28181 注册**的型号，服务器起一个开源流媒体服务（SRS/ZLM）接收——安防行业标准玩法，全现成

| | A：USB+会场电脑 | C：纯网络（IP摄像头+网络拾音器） |
|---|---|---|
| 设备成本 | 摄像头 1500-2500 + 全向麦 900-5000 + **会场电脑**（无则 +500~2000 小主机） | 网络摄像机 300-2000 + 网络拾音器 200-800 + PoE 交换机 ~150，**免电脑** |
| 音画同步 | **白拿**（同机同时钟） | 两条 RTSP 流、两个时钟，**对齐要自己做**（+2~4 天开发） |
| 音频质量风险 | 低（会议全向麦为会议场景调优，DSP 成熟） | **高（最大赌注）**：安防拾音器品控参差、DSP 弱；而远场收音恰是我们的 miss 错误主战场——必须实测 |
| 视频质量风险 | 低（消费 4K 会议摄像头） | 中（安防款曝光/对焦为监控调优，需选会议定位款并实测） |
| 部署便捷 | 依赖会场有电脑/小主机，浏览器常驻 | **最便捷**：插电插网线即走，无人值守 |
| 开发量 | 复用现有 ws 采集（≈0 新增） | RTSP 拉流+解码+重采样+对齐（+2~4 天） |
| 协议形态 | 我们主动推（ws 上行） | RTSP 拉流 / GB28181 设备主动注册 / **FTP 定时传截图（最简，连拉流都省，买前确认间隔参数）**——全现成，SDK 基本用不上 |

**决策规则（一句话）**：会场有电脑（或愿意放个小主机）→ **A 完胜**（零新增开发、同步白拿、音质风险低）；会场必须无电脑无人值守 → C 可行且便宜，但把"网络拾音器远场收音质量"列为 Go/No-Go 第一实测项，不达标就 A+小主机。

**给老师的口径**：两路线都真实可行，麦克风摄像头都有网络直连型号；默认推荐 A（会场电脑方案），若会场无电脑则走纯网络 PoE 方案（设备更便宜、部署更简，需多两天联调）。

**成本/效果的本质对比（2026-09-15 补）**：同等效果下一次性设备价差仅 1000~3000 元（A 贵在免电脑小主机与会议级 DSP），真正差异在**工期**（C +2~4 天流同步开发）与**音质风险**（C 的安防拾音器远场表现未实测，远场恰为系统 miss 错误主战场）。单人死线项目里工期与风险贵于钱——**结论：选 A，除非会场无电脑**。

**给李老师的话术（可直接转发）**：
> 硬件传输两条路线都真实可行、效果都能达标，区别在钱和工期：①接会场电脑（USB 全向麦+摄像头）：设备贵约一两千，但软件零改动、音画同步天然准确、会议级收音最稳；②纯网络设备（PoE 网络摄像头+网络拾音器）：设备便宜、免电脑即插即用，但多三四天开发做双路流同步，拾音器远场效果需实测兜底。想确认：开会那间会议室有没有常驻电脑？有就走①，没有就走②（或加小主机仍走①）。

## 四、D1 实测清单（采购前，手机/现有设备可先行部分项）

1. 拍真实投影 PPT → VLM 读出准确率（摄像头画质指标）
2. 拍手写白板 → VLM 读出准确率
3. 单机位覆盖屏+白板（取景指标）
4. **（若考虑 C）网络拾音器远场收音 vs 全向麦**：同一段说话分别录，接 replay 管线比 DER / 主观听感
5. （若考虑 C）双 RTSP 流时间对齐稳定性（拉流 1 小时看漂移）

# 会议纪要系统整合方案（2026-09-28 v2 · 对齐后修订）

> 前置决定（用户已拍板）：
> - 会中/会末的认人算法**冻结**：3D-Speaker + 声纹库簇级 argmax（v1），不再做任何调优
> - **双版本架构**：实时版（半实时）与会末版是两条独立管道，只复用声纹库 / 视觉(OCR) / 录音来源，
>   **互不纠正**，前端两个 tab 展示
> - G4 资料上传：本期不做，接口预留
> - Word 导出：本期不做
> - 维护目标：**一套轻松维护的代码 + 一个启动脚本 + 两份清晰可见的配置**

## 0. 双版本架构（本方案核心）

```
                    ┌──────────── 开会配置弹窗（前端）────────────┐
                    │ 版本: 只实时 / 只会末 / 都走                   │
                    │ 音源: 麦克风(线下) / 线上会议(屏幕+系统声+门控)  │
                    │ 覆盖项: 热词 / 标题 / 参会人                   │
                    └──────────────┬───────────────────────────────┘
                                   │ 同一份录音 + 同一声纹库 + 同一视觉缓冲
        ┌──────────────────────────┴───────────────────────────┐
        ▼                                                      ▼
【实时版】（半实时）                                    【会末版】（会议结束后自动启动）
3D 分人 + 声纹 → 未识别                                全录音重跑：GTCRN → 3D 全场分人
逐段 ASR + 标点 + ITN                                   → 声纹认人 → 逐段 ASR（全部重跑）
   │ 30/45s 批                                           │ OCR 不重跑，按时间戳直接对齐
   ▼                                                    ▼
L2 波次 LLM：纠错本波 + 订正上波                          按 OCR 波次边界分波（无 OCR 则按时间窗）
+ 段纪要（含待办提取）                                    同一份波次 prompt：纠错 + 段纪要 + 待办提取
   │                                                    │
   ▼                                                    ▼
前端「实时版本」tab（草稿态）                    会末最终总结：全部段纪要归约 + 待办统一清单
                                                前端「会末版本」tab（权威终版）+ 重跑进度条
```

**关键设定**：
- 无声纹命中（含 3D 匿名簇）→ 统一显示 **"未识别"**，不再区分"陌生人N/说话人N"
  （GPU `/identify_segments` 返回的 `说话人N` 由后端统一映射）
- 两个版本**数据完全分离**：实时版落 `utterances`，会末版落 `utterances_re`（表已存在），
  summaries 需加版本维度（见 §3-P2）
- 有声纹时正确度高 —— **已验证**：干净段匹配探针 47/48（98%）、batch 模拟 DER 6.52%、
  M/L 会听感几乎无错。残余错误集中在混簇与重叠区，属算法上限，本期不修。
  → **开会前注册参会人声纹是质量第一前提**（弹窗里要醒目提示）
- 待办提取（本期新需求）：覆盖两类句式——"xx 指派 xx 做 xx" / "我 xx 时间前完成 xx"。
  波次 LLM 顺带输出结构化 `action_items`（任务/负责人/截止时间/原文出处），
  **不额外增加调用**；会末最终总结统一列出全部待办清单
- **视觉(OCR)通道与版本模式无关**：只要开会（无论哪种模式、线上或线下），
  前端就全程抽帧上传。实时版模式下 OCR 随波次（≈2min）走；
  **只会末模式没有波次可挂靠，OCR 改为 2min 独立定时循环**，帧照传照处理——
  所以会末版**始终有 OCR 输入**，不存在无视觉内容的会末版

## 1. 整合目标（维护性）

1. **一套轻松维护的代码**：死代码清理/归档（见 §5），生产路径单一
2. **一个启动脚本 × 各一**：本地全栈 `scripts/start_all.sh`（后端 8010 + 前端静态服务 +
   健康检查）；GPU 服务器侧 `run_supervised.sh`（语音 ASR/认人服务，已有，整理进 scripts/ 并文档化）
3. **两份清晰可见的配置 = 服务器版 + 本地版**（防"本地能跑服务器跑不了"）：
   - `.env.server` —— 服务器部署用，**入库**（内网地址/端口无密钥，pull 下来即能用）
   - `.env` —— 本地开发用，gitignored 不入库
   - `.env.example` —— 模板，入库
   - 切换：`APP_ENV=server|local` 决定加载哪份（缺省 local）；两边**键名完全同构**，
     差异只在值。会议行为参数（批次 30/45、每波 4 批、阈值 0.40、热词）保持代码默认，
     需要按环境覆盖时在同一份 .env 里加键，不另开文件

## 3. 分阶段计划（约 4~5.5 天）

### P0 · 基线（0.5d）
- 全链路冒烟（MAXHUB 录 10min，走完实时批→波次→会末）
- 修挡路 bug；`git tag baseline-20260928`

### P1 · 会中换芯（1d）
- `session.py` 批次：`meeting_chunk` → `denoise_pcm` + `diarize3ds` + `/identify_segments`
  （搬 `batch_3ds_test.run_batch` 逻辑）
- `说话人N` → `未识别` 统一映射（display_speaker 收紧）
- 双音频留存（生肉 + 降噪）入库
- 实测批延迟 / GPU duty cycle；跟不上就批次降频（45/60），**不调算法**
- MAXHUB 真会联调

### P2 · 会末版（1~1.5d）
- 会末触发：会议停止后自动启动（都走/只会末模式均触发），进度经 WS 广播
- 全录音 → GTCRN → 3D 全场分人 → `/identify_segments` → `utterances_re`
- 波次划分：实时版模式下对齐 OCR 波次边界；**只会末模式下对齐 OCR 2min 定时循环的
  输出边界**（两种模式会末版都有视觉输入）；逐波跑与实时版同一份 prompt
  （纠错 + 段纪要 + **action_items**）
- 会末最终总结：全部段纪要归约 + 待办清单聚合
- 数据：summaries 加版本维度（`scope: live|final`，迁移脚本）；action_items 落库
  （新表或 summaries JSON 字段，执行时定稿）
- 与实时版彻底解耦：不再回写 utterances，不互相纠正

### P3 · 前端（1~1.5d）
- 开会配置弹窗：版本选择 / 音源模式 / 热词 / 参会人；**声纹注册提醒**（未注册列表）
- 会议页双 tab：「实时版本」草稿态 /「会末版本」权威态（只开单版本时隐一）
- 会末重跑进度条（百分比/当前阶段）
- 门控"我开麦了"状态显眼提示（漏开 = 自己声音全丢）
- 双版本音频播放回归（生肉/降噪切换）
- 双端响应式：电脑左右分块 / 手机上下分块

### P4 · 常驻化与维护（0.5~1d）
- `vite build` + 静态 serve；systemd user services（后端 + 前端）；`scripts/start_all.sh`
- `.env` 整理 + `.env.example`；新建 `meeting.defaults.toml`；配置加载改读 toml
- §5 归档清理 + .gitignore 补漏
- 更新 AGENTS.md / README（启动、配置、架构一页纸）

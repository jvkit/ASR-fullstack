## 〇、需求终稿（老师确认版）

```
开会时：摄像头(拍PPT) + 麦克风(收音) → 传到我们服务器处理
产出：一份导出的会议纪要（不做问答界面）
补充：会后可通过文件上传接口补充资料（多格式解析，可选）
算法核心：摄像这块 —— 视频不能整段给 LLM（成本爆炸），要从中提取有用的画面
```

**用户（给老师需求做的正确纠偏，v1 已论证）**：不是"对着资料写总结"，而是资料 + 会议上下文融合出纪要。导出物形态：

> 纪要文档 = 会议主题/参会人/事实性属性 + 按时间轴的带说话人转写
> + **各时段对应的幻灯片要点（OCR 文字 + 代表截图）** + 上传资料的要点融合

## 一、关键认知：需求收敛让"最难算法"消失

v1 里预留的"语义级关键帧筛选"（要判断哪帧重要）随着"砍掉问答"**整体不需要了**：

| 原担心 | 收敛后的真相 |
|---|---|
| "视频给 LLM 成本爆炸" | LLM 全程只看文字：转写 + 幻灯片 OCR 文字 + 资料文字。视频帧不进 LLM |
| "截取关键帧是史上最难算法" | 拍 PPT = 静态画面 + 翻页事件。**翻页检测 = OCR 文字差分**（这帧 OCR 文字 ≠ 上帧 → 翻页了）。无神经网络、无理解、可审计 |
| "画面要不要给 AI" | 不用判断：每页存一张代表图（附在导出文档里供人看）+ OCR 文字（给 LLM 用） |

**核心算法链只剩四段工程**：低速率抽帧 → OCR → 文字差分去重（翻页事件）→ 时间轴对齐。全部 CPU 可跑，成本可控。

## 二、传输方案（用户点名的最后一难）

**部署形态：会场一台电脑（或我们部署的小主机）+ USB 摄像头 + USB 全向麦，浏览器打开我们的网页**——音频视频同源同机采集。

```
会场电脑（浏览器开我们的网页）
 ├─ 麦克风 → AudioWorklet 16k PCM ── ws(现有音频管线) ──→ 后端
 └─ 摄像头 → getUserMedia 视频轨 → 本地抽帧 0.5~1fps JPEG
                                    ── ws/HTTP 上行 ──→ 后端
后端：帧接收 → OCR（CPU）→ 文字差分 → 翻页时间轴 → 对齐转写时间轴
```

**为什么传输不难**：
- 纪要场景**不需要视频流**，只需要"幻灯片快照流"——0.5~1 fps 足够（PPT 一页停留几十秒~几分钟），每帧 JPEG 100~300KB
- 带宽估算：1fps × 200KB = 200KB/s ≈ 1.6Mbps，局域网/普通上行都轻松
- 不用推流服务器、不用 RTSP、不用 WebRTC——复用现有 ws 架构加一条二进制通道
- 音画同步白拿：同一台机器同一时间戳
- 断网容错：采集端本地缓存帧，恢复后续传（已有音频管线的断连重连经验可复用）

**备选**（若浏览器长采不稳）：桌面采集客户端（Python/Electron），逻辑相同。

## 三、硬件定标（摄像头升级为必选后的修正）

### 摄像头：第一风险项，到货第一天必须实测

拍屏幕的四大杀手：摩尔纹、梯形畸变、反光、自动曝光漂移。**老师要摄像头≠随便一个摄像头能用**，选型要点：

| 要点 | 说明 |
|---|---|
| 分辨率 ≥4K 或文档模式 | 4K 让 OCR 有足够像素；摩尔纹缓解 |
| 可固定焦距/关自动曝光 | 拍静态画面时自动曝光是敌人（帧间亮度跳变会骗过帧差分） |
| 支架正对屏幕 | 角度越正梯形越小；配上三脚架/夹具 |

候选方向：**USB 文档摄像头/高拍仪类**（为拍文档设计，自动曝光稳）或 4K 网络摄像头（Insta360 Link / 罗技 MX Brio 类）。**Go/No-Go 决策点：W1 D1 用真实投影/电视屏幕实测 OCR 准确率**，不行立刻换型。

### 麦克风：沿用 v1 / `docs/02` 调研结论

全向麦 > 录音笔，USB 有线优先。小会室 eMeet M2 / 中会室 M2 Max / 大会室 Poly Sync 60。**注意新形态：麦接会场电脑**，与视频同源。

### 组合体：仍不推荐

理由同 v1（管线封闭、角度为拍人优化）。

## 四、文件上传接口（老师预留项，不难）

- 端点：`POST /api/meetings/<id>/docs`，支持 pdf / docx / pptx / txt / md
- 解析：python 生态成熟库（pdfplumber / python-docx / python-pptx），PPTX 解析出每页文字其实能直接替代部分 OCR 场景——**会后拿到原始 PPT 上传时，优先用解析文字，摄像头 OCR 只补"讨论时实际展示到哪页"的时间轴**
- 融合：导出时 `content = 资料要点 + 会议上下文` 一起给 LLM（v1 的 enhancer/finalize 提示词扩展）

## 六、给老师的一句话（汇报口径）

> 会议纪要 2.0：开会只需在会场电脑上打开我们的网页，接上摄像头和麦克风。系统自动记录"谁何时说了什么、当时屏幕上是什么"，会后出一份带幻灯片要点的纪要文档，还能补充上传资料一起融合。视频不做整段 AI 分析（成本可控），核心算法是"翻页检测 + OCR + 时间轴对齐"，全部本地部署。

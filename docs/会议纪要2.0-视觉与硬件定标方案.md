# 会议纪要 2.0 · 定标方案 v3（2026-09-15，感知层改 VLM + 白板场景）

> v2→v3 变更（用户拍板）：① **不做 OCR**，感知层全部交给多模态大模型（VLM）
> ——手写白板 OCR 不可行，VLM 对打印体/手写体/版面通吃 ② 场景扩展为 **PPT + 白板**
> ③ 白板采用"状态机 + 增量更新"喂法 ④ 新增数据安全决策点：云 VLM（豆包级）vs 本地 VLM。

## 〇、需求终稿（老师确认版）

```
开会时：摄像头(拍PPT/白板) + 麦克风 → 传到服务器
产出：一份导出的会议纪要（不做问答）
补充：会后文件上传接口（多格式解析，可选），content = 资料 + 会议上下文
感知层：视频不整段给 LLM；抽帧 → 变化检测 → VLM 理解（不做 OCR）
```

## 一、算法链 v3：感知四段

```
摄像头 → 本地抽帧 0.5~1fps（JPEG）──ws──→ 后端
  → ① 图像差分去重（pHash/SSIM，免费工程，非 AI）
      画面没变不送 VLM —— 这是成本开关：2h 会议约 7200 帧，
      差分后通常只剩 ~200 个变化事件（翻页+白板涂写），VLM 调用量降两个数量级
  → ② VLM 结构化理解（唯一的"AI 感知"环节，OCR 已废弃）
  → ③ 视觉状态机（PPT 页序列 / 白板板面状态，增量更新）
  → ④ 时间轴对齐（翻页/涂写事件 ↔ 转写句子时间轴，同机采集天然对齐）
```

**为什么 ② 直接上 VLM 而不是 OCR（v3 的核心理由）**：
- 手写白板：会议手写人类都需猜测，OCR 产出乱码垃圾还会污染纪要——**无解，只有 VLM**
- 打印体 PPT：拍摄有摩尔纹/反光时 OCR 会瞎，VLM 能结合版面语义恢复
- 版面/图表/流程图：OCR 只有文字没有结构，VLM 有
- 一套感知层通吃所有画面类型，架构反而更简单

## 二、VLM 喂法：PPT 与白板是两个物种

### PPT（翻页型，离散状态）
```
变化事件 → VLM: "这页 PPT 的标题、要点、完整文字" → 存为该页快照
导出时: [09:47~10:05] 幻灯片《Q3 预算草案》p7: 要点…
```

### 白板（渐进型，连续状态）—— v3 核心算法点
白板是"写一行、擦一块"的增量演化，逐帧描述会重复、昂贵、前后不一致。
**状态机 + 增量更新**：

```
白板状态 = []  # 当前板面内容条目列表
每次涂写事件 → VLM: "和上一张比，板面发生了什么变化？（新增/修改/擦除了哪些内容）"
            → 增量合并进白板状态
导出时: 板面历史 = [(09:05, 写下"Q3目标：营收+30%"), (09:40, 擦掉第三行), ...]
```

VLM 只见增量，上下文小、成本低、可审计（每条变更有前后截图对照）。

## 三、⚠️ 数据安全决策点（必须尽快拍板）

| 方案 | 感知质量 | 约束 |
|---|---|---|
| 云 VLM（豆包/GPT-4o 级） | 最强，手写白板也稳 | **会议内容出内网**——与立项的"数据安全"红线冲突，需老师/公司明确批准 |
| 本地 VLM（Qwen-VL 系 72B 量化，公司供给） | 打印体稳、白板 decent | 需确认到货时间；**D1 必须用真实白板手写实测** |

用户表态"多模态模型会有的"→ 按本地供给规划，但 D1 实测数据出来前，**不要对外承诺白板识别率**。

## 四、硬件定标（白板加入后的修正）

| 项 | 要点 | 风险 |
|---|---|---|
| 摄像头 | 4K、关自动曝光（防帧间亮度跳变骗过差分）、**视场必须同时覆盖 PPT 屏和白板**（广角固定机位 or 双摄像头/云台，D1 实测决定） | **第一风险** |
| 麦克风 | 沿用 02 调研：全向麦 USB 接会场电脑 | 低 |
| 支架/安装 | 正对、稳定、无人遮挡 | 中（会场协调） |

**D1 Go/No-Go 扩展为三项**：① 拍真实屏幕的 PPT → 本地 VLM 读出准确率 ② 拍真实手写白板 → 本地 VLM 读出准确率 ③ 单摄像头能否同时框住屏+白板。三项全过才进入 W1 后续；不过则换硬件/双机位/上报决策点。

## 五、传输方案（不变，v2 已论证）

会场电脑浏览器开网页：音频走现有 ws PCM 管线；视频 0.5~1fps JPEG 快照流走 ws 二进制通道（~1.6Mbps）；同机采集时间同步白拿。快照流不是视频流，不引入推流/WebRTC。

## 六、文件上传接口（不变，v2 已论证）

pdf/docx/pptx/txt/md 解析入库；导出时 `content = 资料要点 + 会议上下文` 融合。pptx 解析文字比拍摄 OCR/VLM 更准，作为补充路径保留。

## 八、给老师的一句话（不变）

> 开会只需在会场电脑打开网页，接摄像头和麦克风。自动记录"谁何时说了什么、当时屏幕和白板上是什么"，会后出一份带幻灯片要点和白板历史的纪要文档，可补充上传资料融合。核心算法 = 变化检测 + 多模态理解 + 时间轴对齐，本地部署。

# 会议纪要系统 · 工作详细汇报

> 项目：内网私有化部署的**会议转写 + 说话人区分 + AI 纪要系统**
> 周期：2026-09-04 ~ 2026-09-13（8 个工作日，36 个代码提交）
> 约束：数据不出内网（死约束）——所有语音、转写、纪要均在本公司 GPU 服务器与内网完成

---

## 一、项目背景与目标

老板最初设想采购录音笔硬件采集会议音频。调研后明确了本质需求：**数据安全**——只要语音不出内网，直接网页/电脑收音即可，录音笔反而引入格式转换、传输链路等额外环节。经与老师对齐，确定先做**电脑直接录音**方案。

最终目标形态：

- 网页端一键开始会议录音，实时转写并区分说话人；
- AI 实时纠错 + 滚动纪要，会末生成标题/总结/标签/事实性属性；
- 历史会议落库可查、录音可回放、纪要可导出；
- 后续可集成进 RuoYi / 泛微 OA（中间层方案已论证）。

## 二、技术架构（已全部落地）

```
浏览器 (Vue3 + WebAudio, PCM 16kHz 流式)
   │ WebSocket
   ▼
FastAPI 后端 ──┬── FunASR 2pass (GPU:10095)   实时转写 + 说话人标签
               ├── diarize 服务 (GPU:10096)   ERes2NetV2 声纹 / 阿里 pipeline
               ├── LLM 网关 (内网 vLLM)        实时纠错 + 滚动纪要 + 会末总结
               │      └── Langfuse 全链路埋点（每次调用输入/输出/耗时/失败可追溯）
               └── SQLite                     会议/句子/纪要落库，录音存盘
```

| 组件 | 技术选型 | 说明 |
|---|---|---|
| 前端 | Vue3 + Vite + Vant | 手机/电脑自适应；HTTPS 解决浏览器麦克风权限 |
| 后端 | Python + FastAPI + WebSocket | 异步全链路，音频 0.1s 粒度流式处理 |
| 转写 | FunASR Paraformer 2pass | 流式出临时字幕，离线出确定句+字级时间戳 |
| 说话人 | ERes2NetV2 声纹（阿里达摩院） | 盲测完胜 CAM++，详见第三节 |
| LLM | 内网 Qwen（LiteLLM 网关） | 纠错/纪要/属性提取；Langfuse 可观测 |
| 数据 | SQLite + 本地 wav | 数据不出内网；录音回放支持 |

## 三、核心难点一：说话人区分——四方盲测选型

说话人区分（diarization）是本系统最核心的难点。我们没有拍脑袋选型，而是**把业界主流方案全部拉到本地 GPU，用同一批真实会议录音（双人对话、单电脑麦克风）做分轨导出 + 人工盲听 + 声纹余弦相似度量化对比**：

| 方案 | 组成 | 盲测结论 |
|---|---|---|
| FunASR + CAM++ | FunASR 自带说话人聚类 | 基线可用，约 50% 区分率，多人连续说话大量混判 |
| 阿里 pipeline + CAM++ | pyannote 式切分 + CAM++ | 明显优于基线，支持 oracle 人数约束 |
| 阿里 pipeline + **ERes2NetV2** | 切分 + 新一代声纹 | **盲听最佳**：连续说话区分准确、错误率可接受 |
| pyannote（国际口碑最强） | 端到端 diarization | **中文场景意外地差**：碎段多、错误率高，远不及阿里 pipeline |

选型结论：**FunASR（转写）+ 阿里 pipeline（切分）+ ERes2NetV2（声纹）**。

配套测试工作量：

- 录音分轨导出、人工盲听打分、声纹相似度量化评估（63 段逐段对照表，一致率 78%，全部留档于 `docs/eval/`）；
- CAM++ vs ERes2NetV2 **同批注册样本公平竞技**（ERes2NetV2 明显胜出，已实际试听验证）；
- 排查并解决 pyannote/HuggingFace 鉴权、GPU 显存占用、服务化封装等工程问题；
- 另评测过 OddASR（流式不分人）、Aham Voice（同路线，无可借鉴点），书面留档。

**关键认知**：在线产品（reccloud 等）是"录完整段再识别"，我们是实时流式——难度高一档，这个差异贯穿了后续全部调优。

## 四、核心难点二：实时路线的探索与技术收敛

> 结论先行：**实时滚动增强管线已完成自研并跑通，探索后我们主动收敛到非实时方案**。下面先说做了什么，再说为什么收。

**已落地的滚动管线**（在线产品"录完整段再识别"的从容，我们在 8 秒窗口里兑现）：

- **滚动窗口**：有效语音 ≥8s 成窗（不足并入下轮，墙钟 15s 强制成窗）；
- **重叠纠错**：每轮 LLM 输入 = 上轮原文 + 上轮纠正文 + 本轮原文，**允许原地修正上一轮**；
- **滚动纪要**："上轮纪要 + 本轮内容"锚定改写，越滚越准；
- **草稿先行**：原始转写灰色草稿 ~1s 先出，AI 纠错后原地替换。

**探索中确认的难处**（每条均有实测数据，详见第五节排障表）：

1. **双模型精神分裂**：实时标签来自 FunASR 内置 cam++，会后修正用 ERes2NetV2——两套模型、两套阈值、两个准确率水位，排障成本翻倍；
2. **远场命中天花板**：cam++ 对远场轻语音命名率显著弱于 ER（AISHELL-4 远场实测：实时命名几乎全匿名，会后版同音频帧命中 95.6%）；
3. **VAD 粒度与快交替的矛盾**：静音阈值小→切句碎、声纹不稳；大→多人快交替被并成一段混人。无全局最优，只能按场景区间调。

**收敛决策**：实时命名的准确率与维护成本不成正比，而业务价值（纪要、回溯、导出、OA 集成）**全部集中在会后**。故定案：会中录音照常累积，**每 8 秒用好管线增量出"文字+说话人"**（同一套验证过的管线，只是批次执行）、2 分钟滚一次纪要，**会末同管线出权威终版**——砍掉 cam++ 匹配与滚动打标，全系统只剩一个脑子。

### 剩余已知问题（诚实陈述）

1. ~~句内换人~~ **已解决**（滑窗子段切分，见 B 类 #10；单人句误切的反向事故也已修，见 #11）；

## 六、可测性建设（本项目的拐点）

排障速度的质变来自四个工具：

1. **重放测试**：历史录音按真实节奏喂进完整管线——不用重新说话就能复现任意一场会，参数改动 A/B 对照成为可能；
2. **双版本分离**：会中版/会后版两条管线独立展示互不污染，谁的错一目了然；
3. **量化评测**：ground truth 逐句打分 + score_seg 一键声纹打分——从"感觉不对"到"margin 0.004"只差一条命令；
4. **AISHELL-4 标准基准**（第二阶段新增）：业界标准中文会议测试集（211 场真实会议、4-8 说话人、远场麦克风阵列、人工标注），5 分钟一块自动出 DER（说话人日志错误率，业界通用指标）+ 逐错段清单，彻底摆脱"自己录音自己评"的循环论证。

**没有这四个工具，前面 17 个坑里至少一半无法定位。**

## 七、量化成绩与竞品对比

### 7.1 标准基准（AISHELL-4，远场真实会议）

| 测试块 | 场景 | DER | 构成 |
|---|---|---|---|
| S_R003S01C01 0-5min | 小房间 5 人 | **5.0%** | miss 2.3 + fa 2.7 + conf 0.0 |
| S_R003S01C01 5-10min | 小房间 5 人 | **4.5%** | miss 1.4 + fa 2.4 + conf 0.7 |
| L_R004S01C01 0-5min | 大房间 7 人 | 13.7% | miss 10.3 为主（远场漏检） |
| 自录双人对话（近讲） | 日常场景 | 逐句 **8/8** | 人工 GT 全对 |

错段高度集中在两类：**<1s 极短句**（声纹物理极限，程序无解）和**大房间最远端漏检**（VAD 灵敏度问题，可继续调）。

### 7.2 与并行项目（Sortformer 方案）同卷对比

同一份录音 de61a50cde94（55.6s 双人对话，人工 GT），两套系统独立测试：

| 维度 | 本系统（会后版） | Sortformer 方案 |
|---|---|---|
| GT 句子命中 | **6/6 全对**（含"你自己的有录入进去"等快交替句） | 3/6，连续对话被并行成一行 |
| 句内换人 | **已解**（子段滑窗切分） | **未解**（4.5-8.6s 两人话拼一行归一人） |
| 幻影说话人 | 门限抑制（margin<0.04 不拆） | **出现 spk3**（短杂音被分为第三人） |
| 尾部覆盖 | 全程覆盖 | **13 秒未归任何人**（末尾卡在 buffer） |
| 说话人标签 | 真实人名（声纹库直出） | 相对标签 spk1/spk2，仍需声纹库二次映射 |

对方文字转写尚可，分人质量与我们**早期版本**同水位——区别在于这一类问题我们已逐个修掉并量化验证，对方还在原地。

## 八、工作量与难度评估

**做出来不难，做好很难。**

- 基础链路（录音 → 转写 → 展示）一人一周即可打通——事实上我们 1 天就跑通了；
- 但之后的每一步优化都很艰难：
  - **说话人区分**：4 套方案、数十次盲听测试、63 段量化对照，才锁定 ERes2NetV2 组合；实时场景难度再上一档；
  - **16 个坑**：全部"不报错只表现差"，隐性 bug（归一化/时间戳/参数漂移/非确定性）每个都要靠对照实验逼出来；
  - **实时工程**：GPU 服务、LLM 网关每一次抖动都被放大成用户可见故障，逐个做降级/超时/重排；
  - **参数耦合**：VAD、窗口、阈值、纠错范围互相牵连，只能实测迭代——参数唯一化之前，"调参没用"的根因正是三处漂移互相抵消。

量化：**8 个工作日、36 个提交、4 套方案盲测、17 个根因定位、4 个可测性工具、AISHELL-4 标准基准 DER 4.5~5%（小房间）、同卷对比完胜并行项目**。

## 关键事实

1. **阿里官方文档自报 DER：2 人对话 4.7%，2-10 人 8.0%** —— 与"听感 5% 错误"吻合。
2. **阿里官方 README 原话**："如果有先验信息，输入实际的说话人数，会得到更准确的预测结果"——oracle_num 是官方推荐用法，不是作弊。先验人数可由本场匹配到的注册声纹数自动估计。
3. 阿里自动模式（不喂人数）在本录音上坍缩为 1 人（merge_thr 0.5-0.6 均无效），人数估计仍是行业难点。
4. pyannote 3.1/community-1 的 embedding 基于 VoxCeleb（英文为主），中文说话人区分力打折；且碎段倾向明显。
5. 我们的实时管线（流式 VAD + 短句声纹）受结构限制：短句 embedding 差 → 匿名碎片。温和参数改善但不根治。

## 结论（待用户最终听辨确认）

阿里 pipeline（oracle_num 自动估计）作为**会末离线重标注**引擎；FunASR 保留实时转写 + cam++ 声纹标身份；pyannote 出局。

## 2026-09-05 追加：声纹模型换型（cam++ → ERes2NetV2）

### 触发
- 阿里的身份标注其实用的是 cam++（configuration.json 的 speaker_model）——即 "阿里判" = cam++ + 聚类。
- 第一轮分歧段听辨：`seg_117.92_蒋vs冯_ali冯.wav`、`seg_154.46_蒋vs冯_ali冯.wav` 等，用户判 ere 对（"中间那个完胜"）。
- 第二轮交叉验证（5afd 会议）：cam/ere 零分歧，但 `r2_45.77` 段阿里整簇锚定=冯、两模型均高置信=蒋，用户实听"就是蒋，完美" → ere 顶住聚类拖拽。

### 决策
- 身份标注层换 ERes2NetV2，全体重新注册（每 3 秒语音）。
- M1 必须留存 enroll 原始音频（供日后再换模型/复核）。
- 架构：FunASR 实时转写 + 阿里 pipeline 会末切分 + ERes2NetV2 声纹标身份。

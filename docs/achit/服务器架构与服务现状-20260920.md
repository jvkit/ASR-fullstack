## 三、两条处理链路（当前生产）

### 3.1 会中批次（utterances）

```text
浏览器录音 → ws → session.py 攒批（8s 起 / 15s 强制 / VAD 句尾切点）
→ 本地 GTCRN 降噪 → GPU /meeting_chunk（VAD 250ms + SeACo ASR + ERes2NetV2 认人/匿名聚类）
→ utterances 落库 → 前端展示 → enhancer：LLM 纠错 + 滚动纪要
```

### 3.2 会末终版（权威，utterances_re）

```text
整场原始 PCM → 本地 GTCRN 降噪
→ 本地 3D-Speaker（FSMN VAD + CAM++ 嵌入 + 谱聚类）出匿名分段
→ GPU /identify_segments：逐段 SeACo 转写[热词/标点/ITN] + 簇级 ERes2NetV2 声纹认人
→ utterances_re 落库（权威终版，失败不回退旧聚类）
```

关键约定：会末分离在**本地**做（3D-Speaker），GPU 只负责逐段转写+认人（`/identify_segments`）；会中批次仍走 `/meeting_chunk` 旧一体化端点（兼容/回滚保留）。

## 六、易混淆点（只针对本项目）

1. **我们的常驻服务只有两个**：本地 8010 + GPU 10096。GPU 机器上其它任何端口/服务都不是本项目的，不要在架构图里画进来。
2. `:10095`（FunASR WebSocket）是**已废弃**的历史方案，代码在 `funasr-src/` 但服务未运行；声纹注册早已迁到 `:10096` 的 `/speaker_enroll`。
3. 降噪（GTCRN）在**本地**跑、不在 GPU；声纹向量计算在 GPU。别把两者位置记反。
4. 会中（`/meeting_chunk` 自研聚类）与会末（3D-Speaker 分离）是两条路径，**会末以 3D-Speaker 为唯一权威**，失败不静默回退。
5. 所有阈值唯一来源 `server/app/config.py`；GPU 端 Form 默认值必须与其一致。

## 七、维护要点

- GPU 服务重启：`ssh gpu "cd ~/jvkit/asr && setsid nohup bash diarize_svc/run_supervised.sh > /dev/null 2>&1 < /dev/null &"`；手动停先 `pkill -f run_supervised` 再杀 uvicorn，两条分开执行。
- GPU 机器是共享环境（存在其他用户的服务与登录会话），本项目服务有 `run_supervised.sh` 防静默杀死；死亡时间线看 `~/jvkit/asr/diarize_svc_respawn.log`。
- 磁盘可回收项（GPU，本项目名下）：`venv-wlk/` 7.1G + `venv-pyannote/` 7.2G + `wpk-src/` 30M（均已弃用，删除前需确认）。
- 本地 `.venv` 2.1G、`eval/` 11G 属正常体积，勿随意清理。

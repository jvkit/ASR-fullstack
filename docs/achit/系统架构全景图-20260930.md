要点：

- **本地零 torch**（2026-09-30 改造）：降噪、分离、ASR、声纹认人全部在 GPU 服务器；本地后端只做编排（WS 收发、HTTP 调用、写库）。
- LLM 网关 `:4000` 是 OpenAI 兼容代理，后面挂内网 vLLM / 外部 API 均可，后端无感知。
- FunASR 官方 wss 服务（10095）目前**不在主链路**上，仅保留（历史声纹注册管理曾用它）。
- diarize_svc（10096）**完全自包含**：ASR/VAD/声纹/降噪/分离全部以库形式 import 进自己进程（`funasr.AutoModel` / `gtcrn_net` / `speakerlab`），权重读本地磁盘；不调用任何其他服务——不打 10095、不打 LLM 网关、不连数据库。
- GPU 机器 IP 会变：改 `.env` 的 `DIARIZE_HTTP_URL` 即可，不用改代码。

## ④ 会议生命周期时序图

```mermaid
sequenceDiagram
    participant U as 浏览器
    participant B as 后端 session.py
    participant G as GPU :10096
    participant L as LLM :4000
    participant D as MySQL

    U->>B: WS start (title/version_mode/source_mode)
    B->>D: meetings 插行 (status=live)
    B-->>U: started (meeting_id)
    Note over B: 批次循环启动（每 4s tick）

    loop 每 30~45s 一批（VAD 句尾切点）
        U->>B: PCM 帧流（0.1s/帧）
        B->>G: /vad（找句尾）→ /denoise → /diarize_full → /identify_segments
        G-->>B: [{start,end,speaker,text,score,margin}]
        B->>D: utterances + diar_segments 落库
        B-->>U: transcript（草稿态）
    end

    loop 每 4 批 = 1 波（约 2 分钟）
        B->>L: 波次 LLM（纠错+订正上波+段纪要）
        B->>D: summaries(live) + utterances 纠错回写
        B-->>U: transcript_update + summary
    end

    U->>B: stop
    B->>D: 录音落盘，status=ended
    B-->>U: ended（用户立即看到结束）

    par 后台收尾（两版独立管道）
        B->>L: live 终版：段纪要归约 → summaries(live, seq=0)
    and
        B->>G: final 版：整场重跑 reannotate → utterances_re
        B->>L: 会末波次 ×N + 终版总结
        B-->>U: final_progress → final_done
    end
```

状态机：`live`（进行中）→ `ended`（正常结束）｜后端启动时把上次进程残留的 `live` 扫成 `interrupted`（已中断，main.py sweep）。

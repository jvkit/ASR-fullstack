# 优化方向讨论总结（2026-09-14 教学讨论固化）

> 今天围绕"服务器侧还能怎么优"展开的讨论，全部结论固化在此，供后续优化/调试索引。
> 相关学习文档：`learn/001~004`；声纹数据：`eval/声纹两两相似度-20260914.xlsx`。

## 一、已确认的事实（数据支撑，可直接引用）

1. **声纹库安全度**：10 人两两相似度中位数 0.099；男-男对中位 0.300 是最危险区；**admin~蒋泽鹏 0.525 是全场头号危险对**（落在自匹配带 0.44~0.61 内部，成因=同为成年男性+同设备同域录入）。除该对外其余 44 对全部 ≤0.424，缓冲充足。
2. **相似度刻度尺**：本人 0.7~1.0；本人(开会vs注册) 0.44~0.61；危险区 0.30~0.44；普通同事 0.05~0.30；<0.05（含负数）基本无关。
3. **当前错误结构**：混淆已压到每场 1~5 秒（0.4%~1.7%），主战场是 VAD 远场漏检（M会 43s、L会 30s）。
4. **阿里 pipeline（campplus 聚类）现状**：只在 `/diarize` 端点待命，生产 `/meeting_chunk` 未走它；当前管线 = RMS归一化 → FSMN VAD → diarize_sent(ER滑窗认人) → 逐子段 SeACo ASR。
5. **声纹注册质量分布**：admin 3 段对本人质心 0.708~0.861；单段注册的其他人无从验证（补录后可重测）。

## 二、方法谱系（换人检测 ≠ 只有相似度）

| 流派 | 代表 | 对我们的定位 |
|---|---|---|
| 能量/停顿 | VAD | 已有——有停顿的换人免费解决 |
| 统计假设检验 | BIC/GLR (1998) | 考古价值，退役 |
| 滑窗 embedding 相似度 | 我们的现状 + pyannote SCD | 主体（身份层必经之路） |
| 端到端逐帧 | EEND (2019) | 取消"折断点"概念，重叠免费治，门槛=训练数据 |
| 目标说话人 VAD | TS-VAD (2020, ICASSP23 Transformer 版) | **和我们注册库架构最契合**，重叠免费治 |

关键认知：我们要的是"谁"，不只是"换没换"——即使完美切点也须回 embedding 贴名，**相似度对我们是身份层的必需，不是可绕过的步骤**。EEND/TS-VAD 的角色是"重叠检测补强件"而非替代件。共同瓶颈：中文真实会议标注数据（AISHELL-4 是入场券）。

## 三、可落地优化清单（按优先级）

### P0 匿名在线聚类（治坍缩 + 治"说话人201"）
- 机制：匿名窗不再继承邻居，改为维护匿名簇质心列表——≥阈值并入最近簇（滑动平均越说越准），否则新开"说话人K"编号
- 学术对应：UIS-RNN（Google 2018）思想的工程简化版；阿里/pyannote 输出 spk0/spk1 靠的就是这个
- 收益：未注册人整场保持稳定编号；是 AGENTS.md"匿名段聚类（未做）"的具体形态
- 工程：纯 CPU，embedding 已有，~几十行；接入点在 diarize_sent 后处理段
- 产品配合（用户拍板的形态）：**不弹窗**；会后对活跃匿名簇温和提示"说话人2 发言 3 分 20 秒，是否录入声纹？"

### P1 VAD max_end_silence_ms 对照实验（250/400/600）
- 假设：调大保弱音收尾 → miss 降；代价=相邻句缝合 → conf 涨
- 用 M 会 5min（miss 最重 43s）逐档测，盯 miss 和 conf 两个指标
- **注意：用户最初提议调小，分析后方向反了——漏检是"没检出"不是"切不准"，调小无助且引入碎句风险**

### P1 录入相似度检查（enrollment uniqueness check）
- 工具：`pairwise_sv.py`（已建，可导出 xlsx）
- 初始阈值：两两质心 >0.45 硬拒、>0.35 警告（待更多真人数据校准）
- admin~蒋泽鹏这类"耳听全不同、模型 0.5+"的对走警告+重点观察，不硬拒（会误伤真人）

### P2 滑窗四小改（绝佳滑窗设计五条中挑剩的）
1. 峰值定位替代固定中点（距离曲线 argmax 精修切点）
2. 滞回双阈值替代穷人版抖动修正
3. 最小说话时长约束（≥0.5s/≥2窗，治一字劈两人）
4. 多级分辨率（粗窗找候选→细窗精修）——工程最大，放最后
- 参考：[Kaur 2024 滑窗找峰](https://pmc.ncbi.nlm.nih.gov/articles/PMC11578486/)、[pyannote.audio 积木化](https://arxiv.org/pdf/1911.01255v1)

### P3 LLM 语义归属修正（用户脑洞的收敛版）
- 语义连贯性是真信号（"我同意他的方案""不是，我的意思是"暗示换人）
- **红线：不让 LLM 在批次纠错里静默改归属**（违反事实性原则）
- 正确姿势：会后环节 LLM 提修正建议+理由，人一键确认（接"快捷标注"功能）；机器找疑点、人做裁决

### P3 录入质量引导
- 每人 ≥3 段、安静环境、好设备（admin 3 段 vs 单段的对照就是证据）
- 蒋泽鹏补录 2 段后重跑 pairwise，验证 0.525 是否回落——验证"多段录入治危险对"推理的直接实验

## 四、讨论中收敛掉的思路（记录原因，防重提）

| 思路 | 结论 |
|---|---|
| 波形幅度跳变找换人 | 方向对（间断点检测），观测量错——幅度被"说的内容"主导（声母韵母差异>>换人差异）。正解=embedding 空间（内容剥离版波形变化）；折中=F0 跳变 |
| 间隔统计当换人的判据 | 前提在最难区反了：换人接话快（200~500ms）、思考停顿长（1~2s），中间地带恰好真换人密集。救法=降级为辅助特征：超长间隔(>1.5s)边界基本必换人；超短间隔+距离峰=可疑无缝换人。**可量化验证**：用 rttm 画"换人前间隔 vs 同人停顿"两张直方图（待跑） |
| 调小 VAD 耐心值 | 见 P1，方向反了 |
| BIC/GLR | 退役 |
| 硬拒绝相似声纹对 | 会误伤真人（admin~蒋泽鹏就是活例），改警告+观察 |

## 六、能力边界（诚实清单，非 bug 不修）

- 插话 <0.3s：窗内素材不足，数学上无解
- 重叠说话（两人同时出声）：所有 pipeline 的难题，短期靠"谁大算谁"，长期靠 TS-VAD/EEND
- 声纹跨域下降：注册域≠会议域时命中率降，靠录入引导缓解
- 远场信噪比：归一化只救响度救不了信噪比，**归硬件**（这是"要录音笔"论点的技术根基）

## 1. 声纹稳定性：注册时长到底要多久？✅ 已调研

**外部数据（不用自己做实验了）：**

| 来源 | 关键数据 |
|---|---|
| [Speaker recognition in noisy conditions（ResearchGate）](https://www.researchgate.net/publication/266602834_Speaker_recognition_in_noisy_conditions_with_limited_training_data) | **5s→10s 注册，识别率从 77.7% 跳到 85.9%**；10s→20s 再到 93.3%。30s 后基本饱和 |
| [ERes2NetV2 论文（我们用的同款模型）](https://arxiv.org/html/2406.02167v1) | 短语音验证：3s 测试 EER 0.98%、2s 1.48%；full-duration（约 30s+）EER 0.61% |
| [声网声纹注册 wiki](https://www.shengwang.cn/blog/blogdetail/voiceprint-enrollment-wiki/) | 行业惯例注册 3–10s |
| [InterSpeech 短语音验证评测](http://www.interspeech2020.org/uploadfile/pdf/Mon-SS-2-6-2.pdf) | 注册平均 7.6s/人即可达到可用 EER |

**结论：**
- **有效语音 10–20 秒是甜点**，30 秒后收益急剧递减（几乎饱和）
- 我们 config 的 `min_effective_sec=10s` 方向是对的，但 **001-M 事故说明"压线 10s"不够稳**——纯体检数据在干净环境下 10s 够用，但会议场景（噪声、远讲、插话）要把下限提到 **20s** 才安全
- `max_keep=5` 不亏：embedding 求均值后 5 段（约 15–25s 有效）已过饱和点，再加段数基本无收益
- **5min vs 2.5min 注册**：差别微乎其微，都远超饱和点。真正影响识别率的不是注册时长，而是**注册音频的干净度**（有没有混进别人声音/噪声）

**行动项：**
- [ ] config `enroll_min_effective_sec` 10→20s（压线注册是翻车重灾区）
- [ ] 注册 UI 加质量反馈：注册后自测相似度，<0.6 红色警示"建议补录"（不用删，补录会稀释脏质心）

**结论：** ✅ 已拍板方向：提下限到 20s + 录入质量反馈

## 3. 声纹赃了 → 清洗策略 ✅ 方向已定（待执行）

**现状：** 这次没听就注册了一堆，库里质量未知。声纹库无版本/回滚，同名累积无法撤单次。

**方案候选：**
- A. 全删重录（彻底，代价是要人再念一遍）
- B. 只删自测分数低的（用 identify 批量自查打分）
- C. 保留但补录稀释（脏质心被新段均值拉回来，但脏段还在 max_keep=5 里占坑）

**结论：** 不用全删——补录稀释 + 录入检测自查（#2 做了就能批量发现弱的）。压线注册进不来的（#1 提了 20s 下限）自然被拦。个别特别脏的（试听确认混了别人）单独删。

## 4. 「重跑/重放」合并入口 + 分级配置弹窗 ✅ 设计已对齐（待实现）

**现状：** 「重新标注」按钮 = 一刀切全量重跑（2h 会实测 ~27min）；「重放测试」是独立按钮。

**已对齐的方案：**
```
[⟳ 重跑/重放] 弹窗：
  数据源：(•) 原始录音  ( ) 重放测试
  起点单选（其后全跑）：
    (•) 从转写   ~5min    ← 默认（注册新人刷纪要）
    ( ) 从分离   ~18min   声纹大改重新认人
    ( ) 从降噪   ~20min   换降噪参数
    ( ) 全量     ~22min   换分离模型
  ☐ 重跑 OCR（默认不勾=复用视觉笔记）
  ☐ 会末总结（默认勾；不勾=只出转写+段纪要，调 prompt 用）
```
- 拆分段落：重标注（降噪→分离→转写认人）→ 并行波次 → 会末总结，每段可跳过
- 用户原则：这个功能就是为调试服务的，能拆就拆，但别过度设计

**结论：** 设计已对齐 ✅，待实现

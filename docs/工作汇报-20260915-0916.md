# 会议纪要系统工作汇报（2026-09-15 ~ 09-16）

## 一、本周工作概述

本周工作围绕一个核心目标：**把"说话人区分"这个系统里最不确定的环节，从"感觉不错"变成"可量化、可复现、可审计"**。

做法是建立了一套盲测评测体系（清空声纹库、用带人工标注的公开会议数据集重放），把"认人"和"聚类"解耦后分别定量，再用数据驱动的方式定位并修复问题。两天共完成 **4 轮算法改动、20+ 场对照实验、3 个诊断工具、5 个工程工具/纪律**，最终把盲测聚类错误率压到接近 VAD 物理下限，并**用机制级证据定位了剩余问题的天花板**。

## 二、周二（09-15）：生产化改造——声纹库与注册流程

### 1. 声纹库"假删除"根治（单库改造）
- **问题**：声纹有两套互不通气的存储，删除只删其一，出现"删了照样被认出"和"幽灵名单"。
- **方案**：收敛为唯一权威库（GPU 端 `speaker_enrolls/*.pcm`），注册/列表/删除/检测四个端点统一走一个服务。
- **附带完成**：智能注册管线（VAD 切段 → 音量/爆音过滤 → 一致性双规则 → 多段质心，替代"录 3 秒就入库"的粗放方式）；录入质量检测（说 3~10 秒即报"库中最像谁"，兼作注册自查）。

### 2. 认人阈值定为 0.40
- 依据实测误匹配证据（同事说话误配 0.389、咳嗽误配 0.5+），并经 DER 评测验证收紧代价在噪声内。

### 3. 匿名说话人聚类（方案 A）
- **问题**：未注册说话人被"继承相邻句标签"的错误染色（实测整场会被染成同一个错误人名）。
- **方案**：匿名段不再继承邻居，改为与库中匿名簇匹配 + 批内聚类，陌生人编号跨批次稳定。

### 4. 补录机制（联合重选）
- 旧逻辑"新段 vs 旧质心 ≥0.45 才收"会跨环境误杀；改为新旧段同池民主重选（地板规则），并用真实案例（蒋泽鹏）验证：补录会议室域片段后，旧域外段被自动票出。

### 5. 发现"冯忠俊污染"案例
- 合并质心过于普适（万磁王），在本人没说话的会议里被误贴 6 句。结论：宽质心继续吸人，必须删除+重录（待执行）。

## 三、周三（09-16）：盲测体系与四轮算法迭代

### 1. 建立盲测评测体系（当日最重要的事）

| 工具/纪律 | 说明 |
|---|---|
| 声纹库备份 | 整库打包（73 条），本地+GPU 双份 |
| 清空纪律 | 任何清空必须明确指令；实验记录 `eval/tuning_log.md` 每场必记 |
| `shuffle_meeting.py` | 把"一人讲一大段"的评测音频打散成交错短段（seed 可复现），解决评测太简单、"背答案"问题 |
| `replay_der.py` 修复 | **关键 bug：陌生人标签多于真人时，评分脚本只映射字典序前 6 个标签，大簇永远轮不到映射，DER 虚高至 99%**。修复前后同一会议 DER 从 99.4%→24.9% |
| 多会议交叉验证 | 任何改动至少 3 场未测过的数据验证，串行测试、一次一个变量 |

### 2. 第一刀：修复"空库不出向量"bug + 调参定地板

- **盲测第一场就抓到大 bug**：声纹库为空时代码不算 embedding，5 分钟会议产出 187 个陌生人簇。修复后降到 30 个。
- 段间相似度标定（自写诊断工具）：同一人段间相似度 p10=0.66 / 跨人最高 0.58（女女）——**0.35~0.45 的聚类地板有理论依据**。
- 参数扫描（完整重放口径）：入簇地板 0.45→0.40→0.35 单调改善（24.3%→21.4%→19.1%），**0.30 开始过合并**（两人被合成一簇、一人被拆两簇，用户亲见并确认），拐点锁定 0.35。

### 3. 第二刀：发现"同人别名卡 margin 门"（A/B 实验证明）

- M 会全员已注册盲测 DER 却 33%：库里同一个人有两个名字（跨会议注册的别名），margin 门限（防换人的保护）被"自己人"触发，本人被挡在门外变成陌生人。
- 对照实验：同 4 句话，删掉别名后整句正确命名；有别名时碎成 13 段。
- 结论：库卫生是工程纪律问题，后续注册需加"查重提示"。

### 4. 第三刀：两次确认制 + 尾音归属 + 显示降级（v3，见效）

针对碎段问题（校长说"呃"被识别为新的人）做的三项设计：

1. **两次确认制**：孤段不自立簇心，同一声音出现第 2 次才发正式编号（复用 0.35 地板，无新阈值）；
2. **尾音归属**（会末）：孤段先对成熟簇重比（吸收），再对前后相邻簇比相似度选边贴附，两边都不像则诚实标"未识别短语音"——**只处理孤段、只靠相似度选边**，与此前翻车的"无条件染色"本质不同；
3. **显示降级**：<3s 的簇不显示编号。
4. **全量决策日志**：每个段的每次去向（入簇/候选/升级/踢出/贴附/不贴+相似度分数）都落 GPU 日志，可回答"错了是贴错的还是算错的"。

**效果**：M 会 23 个标签→5 个，DER 19.1%→18.5%；尾音贴附 4 例、诚实不贴 16 例，全部有分数可查。

### 5. 快交替难题的定位（最有价值的"失败"）

- 用打散脚本构造**三人严格交替（每轮 1.5s）**测试：DER 65%，主簇纯度仅 44~57%——把系统软肋逼出来了。
- 逐段化验（对三个真人的干净质心打分）：28 例错配中 **24 例向量本身就模糊**（真人和别人只差 0.01~0.1），仅 4 例是程序放置错误。
- 对照实验（轮次加长到 ~12s）：DER 降到 32%、纯度 81~86%。**证实：轮次越短死得越惨，病根在短轮次的向量信噪比，不在 VAD 切分。**

### 6. 第四刀：簇心加固（v4，证伪）

- 实现"入簇权重=相似度×时长（低相似段拉不动簇心）+ 升级时稳健定形 + 离群踢出"。
- 结果：三场 DER 零变化，**升级踢出机制触发 0 次**——错配段两两相似度 0.64 vs 0.65，全都高于地板，在算法眼里"就是一家人"。
- **结论：快交替残留是 ERes2NetV2 对 ~1.5s 短轮语音的向量区分度极限（模型层天花板），聚类逻辑无解。** 就此止损，不再投入。

### 7. VAD 漏检体检（顺手定位了最大存量）

对 43s 漏检做帧级解剖：**没有一整句丢失**，是摊在 32 个轮次上的系统性边界侵蚀（轮内低声短音 24.5s + 头尾边界 17.8s，其中约一半属人工标注边界比声学边界宽、非真漏）。下一步优化方向：参数扫描 / Silero VAD A/B。

## 五、结论

1. **"做出"不难，"做对"每一步都很艰难**：两天 4 轮改动里 2 轮见效、1 轮证伪止损、1 轮是评测自身 bug——真实优化的常态是用数据排除错误方向。
2. 当前系统状态：**长段/正常轮次会议，聚类已近 VAD 物理下限（M 会 conf 仅 9s）；碎段/尾音有产品级兜底；快交替（<2s 轮次）确认是模型层极限，如实记录不再投入**。
3. 下一步优先级：① 恢复声纹库回归生产场景（命名通道才是真实形态）；② LLM 纠错顺带输出标点（零成本）；③ VAD 边界优化（参数扫描→Silero A/B）；④ 声纹库查重提示防别名污染；⑤ 冯忠俊条目删除重录。

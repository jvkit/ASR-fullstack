# 003 · 换人边界：为什么"最后一个字总被归给下一个人"

> 目标：读完能理解这个经典 bug 的产生机制，以及现在管线里治它的四道工序分别干什么。

## 1. 现象

A 说完一句话，B 接着说话。结果展示出来：

```
蒋泽鹏: ……这个方案我觉得可以。
admin: 对。（其实"对"前面还有半句蒋泽鹏的收尾音）
       ^^ A 的最后一个字/半句被贴到了 B 头上
```

字是 A 说的，标签是 B 的。这就是**换人边界放错了位置**——切点不是落在两人之间的静音里，而是落在了 A 的尾巴上。

## 2. 根因：三个因素叠加

### 因素一：人说话收尾是"渐弱"的

A 说最后一个字时音量天然衰减（"……可以。"的"以"很轻），而 B 起句往往干脆利落。渐弱的尾音对声纹模型来说是**劣质素材**——embedding 不稳，容易被判成"不像 A"。

### 因素二：滑窗检测有"滞后"

我们的换人检测是滑窗：0.6 秒一个窗、0.3 秒挪一步，每个窗独立认人。假设真实换人点在第 5.0 秒：

```
        A 说        |  B 说
 ──────────────────┼────────────►
  窗3: [4.2~4.8] → A
  窗4: [4.5~5.1] → ???  4.5~5.0 是 A，5.0~5.1 是 B，这窗"半像 A 半像 B"
  窗5: [4.8~5.4] → B    大部分已经是 B 了
```

窗4 是过渡窗，判谁都有可能。如果 naively 用"第一个判成 B 的窗的起点"当边界，切点 ≈ 4.5s——**A 从 4.5s 到 5.0s 的半秒收尾全被划进 B 的段里**，最后一个字就归了 B。

### 因素三（旧架构放大器）：碎段继承邻居

旧实时版里，尾巴碎段认不出来就"继承邻居标签"——A 的尾巴碎段挨着 B，直接整段染成 B。三重叠加，尾字必丢。

## 3. 现在管线里的四道防线

按执行顺序（代码在 GPU `diarize_svc/service.py` 的 `/diarize_sent`）：

### 防线一：整句预检，能不拆就不拆

整句 embedding 高置信（≥0.30 且领先第二名 ≥0.10）→ 判单人句，根本不拆。

```
为什么有用：如果整句都是 A 说的，不拆就不会产生切点，尾字无从丢起。
大部分句子走这条路，它们是安全的。
```

### 防线二：change_margin（0.04）——换标签要有"稳定领先"

每个滑窗不是"A 分数最高就贴 A"，而是要求**top1 领先 top2 至少 0.04** 才敢贴名字。

```
为什么有用：A 的弱尾窗里，A 的分数掉下来、B 的分数追上来，
"领先不足 0.04" → 这个窗判"没把握"，不急着换人。
宁可延迟换，不把 A 的尾巴匆匆送给 B。
```

### 防线三：抖动修正——孤立的"换人"不可信

某个窗的标签和前后两个窗都不同 → 判定为抖动，回退成前一个的标签。

```
A A A B A A A   →  那个孤立的 B 被压回 A
```

### 防线四：边界取重叠区中点（最关键的一道）

确认换人后，切点不是"B 的首窗起点"，而是：

```
切点 = (A 的最后一个窗的终点 + B 的第一个窗的起点) / 2
```

**为什么是中点**：两个相邻滑窗必然共享一段重叠区（窗长 0.6s、步进 0.3s，相邻窗重叠 0.3s），真实换人点就藏在这个共享区里——它在 A 的窗里"半像 A"，在 B 的窗里"半像 B"。既然两边都拿不准，那就**各打五十大板**：从中点切开，A 让出前半截模糊区，B 承担后半截。平均而言，切点误差从"最多 0.6s"缩到"±0.15s"，最后一个字大部分时候能留在 A 的段里。

### 附加：ASR 逐子段（展示层不再串台）

就算切分偶尔还是偏了，v2 的 ASR 是**每个子段各自转写**，文字严格跟子段时间走。旧版 v1 是整句转写再把文字复制到每个子段——那时切点一偏，文字还会整句串台，错上加错。现在切点偏 0.1s 只是标签小错，不会带崩文字。

## 4. 现在好了吗？——数据说话

帧级 DER 里的"混淆"（conf，即时间轴上标错人的部分）：

| 会议 | 混淆 | 占总语音 |
|---|---|---|
| S 超市会 | 1s | 0.4% |
| M 幼儿园会 | 5s | 1.7% |
| L 大会 | 5s | 1.0% |

边界问题还存在（不可能归零），但从"最后一个字必丢"降到**每场会几秒量级**。剩下的边界错误主要集中在：抢话/重叠说话（两人同时出声，谁大算谁的，本质无解）、超短句（<0.5s 没有足够素材认人）。

## 5. 和 VAD 实验的关系——为什么扫大反而要小心

还记得 001 里说的吗：调大 `max_end_silence_ms` → 相邻两句话更容易被**缝成一句** → 句内换人变多 → 更依赖滑窗拆句 → 边界压力上升。

所以这个实验要同时盯两个指标：

- **miss 降了吗**（漏检改善，赌它保住弱音尾巴）
- **conf 涨了吗**（句内换人变多，边界错误回潮）

如果 600ms 档 miss 只降一点点、conf 却明显涨，就说明"缝句"的代价大于"保尾"的收益，回 250 或取 400。这就是对照实验的意义：两个方向的力量摆在天平上，数据裁决。

## 6. 一句话总结

"最后一个字归给下一个人" = **渐弱尾音素材差 + 滑窗检测滞后 + 切点偏到 B 侧**。治法是四道防线：能不拆就不拆（整句预检）、换人必须稳定领先（change_margin）、孤立换人压回（抖动修正）、切点各打五十大板（重叠区中点）。现在混淆已压到每场几秒，残余主要是抢话和超短句——那属于模型能力边界，不是工程能修的。
